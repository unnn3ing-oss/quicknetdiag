# 家用網路醫生（netdiag）

自動偵測「連線卡頓、頻繁斷線、WiFi 連線問題」的成因，幫你分清楚問題到底是出在：

- **WiFi 訊號／路由器**（區網本身不穩）
- **ISP／數據機**（區網正常但對外連不出去）
- **DNS 伺服器**（能連上 IP 但網域解析不到或很慢）

單一 Python 檔案，不需要額外安裝套件，Mac / Windows / Linux 都能跑。

## 需求

- Python 3.8 以上（Mac / Linux 通常內建；Windows 到 [python.org](https://www.python.org/) 下載安裝）
- 系統本身要有 `ping` 指令（三大平台都內建）

## 使用方式

### 單次快篩

```bash
python3 netdiag.py
```

會自動偵測路由器 IP，測試：到路由器的延遲/遺失率、對外連線（Cloudflare／Google DNS）、
幾個常見網域的 DNS 解析時間、WiFi 訊號強度，然後印出診斷結果與建議。

### 長時間監控（抓間歇性斷線最好用）

間歇性斷線常常「當下想測就沒事，你不注意的時候才斷」，所以真正有用的是背景長時間監控：

```bash
# 監控 1 小時，每 5 秒量測一次（預設間隔）
python3 netdiag.py --monitor 3600

# 持續監控直到手動按 Ctrl+C
python3 netdiag.py --monitor 0

# 監控並把每筆量測記錄到 CSV，方便之後用 Excel 畫圖看趨勢
python3 netdiag.py --monitor 0 --csv wifi_log.csv --interval 3
```

監控結束（時間到或 Ctrl+C）時會印出總結：斷線次數、最長斷線時間、平均延遲/抖動、
WiFi 訊號範圍，以及根據數據做的整合判斷（例如「區網穩定但對外遺失率偏高 → 問題在 ISP」）。

建議做法：把它丟到背景跑一整天（尤其是常常卡頓的時段），隔天回來看 CSV 或總結，
就能知道斷線是不是集中在特定時間（例如晚上尖峰、鄰居下班用網高峰）。

```bash
# 背景執行範例（Mac/Linux）
nohup python3 netdiag.py --monitor 0 --csv wifi_log.csv > netdiag.log 2>&1 &
```

### 其他參數

| 參數 | 說明 |
|---|---|
| `--gateway IP` | 手動指定路由器 IP（預設自動偵測，抓不到時用這個） |
| `--target NAME=HOST` | 額外加測的目標，例如 `--target 公司VPN=10.0.0.1`，可重複使用 |
| `--count N` | 單次快篩時每個目標的 ping 次數，預設 8 |
| `--no-color` | 關閉終端機彩色輸出 |

## 判斷邏輯（簡化版）

| 現象 | 判斷 | 建議方向 |
|---|---|---|
| 路由器完全無回應 | 區網／裝置本身斷線 | 檢查路由器/AP 電源、Mesh 節點回程 |
| 路由器有回應但遺失率高 | WiFi 訊號或干擾問題 | 靠近 AP、換頻道、排除微波爐/藍牙干擾 |
| 路由器延遲/抖動偏高 | 2.4GHz 壅塞或 Mesh 回程差 | 切 5GHz/6GHz，或改有線回程 |
| 區網正常但對外連線異常 | ISP／數據機問題 | 重開數據機、回報電信業者 |
| 能連 IP 但網域解析失敗 | DNS 伺服器問題 | 改用 1.1.1.1 或 8.8.8.8 |
| WiFi 訊號弱（<-70dBm 或 <40%） | 距離/阻隔造成訊號弱 | 靠近 AP、增設 Mesh 節點 |

實際輸出會依當下量到的數字給出更明確的建議。

## 已知限制

- WiFi 訊號讀取依平台而異，且部分系統（例如新版 macOS 拿掉了 `airport` 指令、或用有線網路）
  可能讀不到，這種情況下腳本仍會正常執行其他測試，只是不會顯示 WiFi 訊號。
- 需要系統本身有 `ping` 指令的執行權限；企業/防火牆環境可能封鎖 ICMP，導致誤判為斷線，
  這種情況可用 `--target` 換成你確定會回應 ping 的內部主機測試。
- 這是本機診斷工具，測的是「你這台電腦到路由器/外部的連線品質」，不是路由器本身的系統紀錄；
  如果路由器有自己的日誌功能（多數 Mesh 系統 App 都有），可以互相對照。
